About Epistery Scan

Epistery Scan is a registry of things with known origin. It indexes data and services that have been signed by their author, so that an AI agent or a person can find them, verify who published them, and retrieve the live source on demand.

Scan does not scrape, rank, or interpret. The single requirement for indexing is that the object was signed by an origin that can be traced. The web was not built with keys, so it has no continuity of identity, and reputation accrues only inside the platforms that grant it. Scan supplies the missing substrate: a place where a signing identity accumulates a verifiable history, and where the value of that history is judged outside the index.

The purpose

AI systems now consume the live web and must trust it. Web content is frequently stale, shaped for search placement, and difficult to attribute to an origin. Scan exists so that a result can instead be a signed, current, navigable object with a cryptographic trail back to its publisher.

The index is not intended as a business in itself. It is infrastructure — a tool first, and eventually a utility. Several ventures depend on it; it is the shared layer beneath them.

How it works

Scan is a registry that knows documents it does not manage. Each data source has an import engine that normalizes its objects into one searchable shape, preserving the author's type, intent, and provenance, so that a single query reaches every indexed type at once. Every object carries three tiers of fields, loosely typed:

  • Required — origin, source, type, and the time the object was first observed
  • Known — the fields implied by the object's type
  • Arbitrary — whatever else the author signed, carried verbatim

Scan stores a searchable digest and a locator: a handle to the live, signed source. The origin is the record; the index is a pointer to it. When a result is acted on, the locator is retrieved and the origin's signature verified at that moment, so the content is current and provably from the source. Scan hands over the handle and does not re-serve the content, which would break the signature chain.

Trust without an arbiter

Scan does not compute a trust score. Scoring is interpretation, and an interpreter is an arbiter — the role Scan exists to remove. Every result instead carries the verifiable facts from which trust is derived by the consumer: a person, an agent, or this site's own surface.

  • chain-bound — the signing identity has an on-chain contract bound bidirectionally to its domain
  • dns — the domain owner authorized this publication
  • claimed — signed by a self-asserted key, not yet domain- or chain-bound
  • open — published, unsigned

Alongside the rung, Scan reports the signature facts (signed, verified against an on-chain identity, method) and the origin's age, derived from the first event observed for it. The duration of a signing history is reported as a fact and weighed by the consumer. Badges shown on this site are computed at the surface from these facts and can be recomputed independently.

For AI agents

Agents are the primary audience. Every result is returned in one fixed envelope, present.ai, identical in shape for every object type, so that a client can bind to it once: 

{
  "type": "vehicle",
  "headline": "2019 Honda Civic LX — 41k mi",
  "summary": "One owner, clean title.",
  "origin": {
    "address": "0x9f…",
    "rung": "chain-bound",
    "since": "2022-03-01",
    "signature": { "signed": true, "verified": true, "method": "ecdsa" },
    "signals": { "contractExists": { "present": true }, "domainBinding": { "present": true } }
  },
  "freshness": { "observed": "2026-06-20", "live": ["price", "status"] },
  "locator": { "fetch": "https://dealer.example/inv/8842", "kind": "signed-json", "yields": "vehicle" },
  "facets": { "make": "honda", "model": "civic", "year": 2019, "price": 18900 },
  "actions": [ { "name": "contact_seller", "invoke": "https://dealer.example/contact/8842", "needs": "none" } ]
}

The facets are loose and source-shaped; the envelope around them is fixed. origin carries facts, not a score. freshness.live names the fields whose stored value is a hint only — the locator must be retrieved to trust them. actions are advertised, not brokered: each resolves to the origin's own endpoint and is invoked with the caller's epistery identity.

For publishers

Publish a signed /.well-known/ai manifest describing yourself and how you wish your content shared, and Scan will discover, index, and present it. The publisher controls the representation, and the origin remains provably theirs. The AI Discovery Standard and its plugins generate that manifest. Enter a domain in search, or use the Discovery page to check any domain.

Sample queries

blockchain — find organizations publishing about blockchain technology identity — discover identity and authentication services rootz.global — look up a specific domain's manifest and origin facts AI Discovery — search indexed concepts across all signed domains

Help & support

What the badges mean — the legend for the trust badges, signal dots, and source labels shown on every search result. Every badge in the results links there. For publishing and API questions, see Developers or the AI Discovery Standard.

Status: the fixed present.ai envelope, the origin rung, signature facts, age, history depth (an origin's count of indexed objects), locator, and advertised actions are live for indexed objects today. Per-type volatility declarations — which fields are live hints rather than stored values — are the next increment, declared here and under construction. Where this page describes more than the code implements, the code is what changes.
