About Epistery Scan

Epistery Scan is a registry of things with known origin. It indexes data and services that have been signed by their author — a car listing, an identity contract, an advertising campaign, a shipment of produce, a page of recipes — so that an AI agent (or a person) can find them, verify who published them, and pull the live source on demand.

We do not scrape, rank, or interpret. We require only one thing: that what we index was signed by an origin you can trace. The web was never keyed, so it never had continuity — and without continuity, reputation has nowhere to accrue except inside a handful of platforms that grant it. Scan is the missing substrate: a place where a signing identity can build a verifiable history, and where the market — not Scan — decides what that history is worth.

The purpose

AI now has to consume the live web and trust it, and the live web is a poor source: stale, wrapped in SEO sludge, and impossible to attribute to its origin. Ask a model for a used Honda Civic in northern Arizona and it goes to Reddit — an opinion of unknown age from an account of unknown provenance. Scan exists so that the answer can instead be a signed, current, navigable object straight from the dealer, with a cryptographic trail back to who published it.

We are not trying to make a business of the index itself. It is infrastructure — a tool first, and one day a utility that disappears into the fabric of the web. Many ventures need it; this is the shared spine they stand on.

How it works

Think of Scan as an interplanetary Mongo: a registry that knows documents it does not manage. Each data source has an import engine that normalizes its objects into one searchable shape — preserving the author's type, intent, and provenance — so a single query reaches vehicles, contracts, identities, and signed pages at once. Every object keeps three tiers, Mongo-style and loosely typed:

  • Required — origin, source, type, and the time we first knew it
  • Known — the fields a type implies (a vehicle carries a VIN; a campaign carries rates)
  • Arbitrary — whatever else the author chose to sign, carried verbatim

Scan stores a searchable digest and a locator — a handle to the live, signed source. The origin is the truth; the index is a pointer to it. When a result matters, the locator is pulled and the origin's signature is verified at that moment, so what you act on is current and provably from the source. Scan hands over the handle; it does not stand in the middle and re-serve the content. The moment it did, it would break the very signature chain that makes it worth using.

Trust without an arbiter

Scan has no trust score. Scoring is interpretation, and an interpreter is an arbiter — the role we exist to remove. Instead, every result carries the verifiable facts from which trust can be built, and you (or your agent, or this site's own surface) build it yourself:

  • chain-bound — the signing identity has an on-chain contract bound bidirectionally to its domain
  • dns — the domain owner authorized this publication
  • claimed — signed by a self-asserted key, not yet domain- or chain-bound
  • open — published, unsigned

Alongside the rung we report the signature facts (signed, verified against an on-chain identity, method) and the origin's age — derived from the first event we observed for it. A key that has been signing for years is a different proposition than one minted yesterday; Scan states that as a fact and lets you weigh it. Any badge you see on this site is computed at the surface from these facts, and you can recompute it.

For AI agents

Agents are the real audience. Every result is returned in one fixed envelope — present.ai — identical in shape for a car, an identity, or a pallet of lettuce, so a client can bind to it once and rely on it every time: 

{
  "type": "vehicle",
  "headline": "2019 Honda Civic LX — 41k mi",
  "summary": "One owner, clean title.",
  "origin": {
    "address": "0x9f…",
    "rung": "chain-bound",
    "since": "2022-03-01",
    "signature": { "signed": true, "verified": true, "method": "ecdsa" },
    "signals": { "contractExists": { "present": true }, "domainBinding": { "present": true } }
  },
  "freshness": { "observed": "2026-06-20", "live": ["price", "status"] },
  "locator": { "fetch": "https://dealer.example/inv/8842", "kind": "signed-json", "yields": "vehicle" },
  "facets": { "make": "honda", "model": "civic", "year": 2019, "price": 18900 },
  "actions": [ { "name": "contact_seller", "invoke": "https://dealer.example/contact/8842", "needs": "none" } ]
}

The facets are loose and source-shaped; the envelope around them is rigid. origin is facts, never a score. freshness.live names the fields whose stored value is only a hint — pull the locator to trust them. actions are advertised, never brokered: each resolves to the origin's own endpoint, invoked with your epistery identity. The intended habit is simple — ask your agent to “find me a used Honda Civic in northern Arizona, use epistery” and let it navigate signed objects instead of scraping opinions.

For publishers

Publish a signed /.well-known/ai manifest describing yourself and how you wish your content shared, and Scan will discover, index, and present it — with you in control of the message and the origin provably yours. The AI Discovery Standard and its plugins generate that representation for you. Enter your domain in search, or use the Discovery page to check any domain.

Sample queries

blockchain — find organizations publishing about blockchain technology identity — discover identity and authentication services rootz.global — look up a specific domain's manifest and origin facts AI Discovery — search indexed concepts across all signed domains

What the badges mean — the legend for the trust badges, signal dots, and source labels shown on every search result. Every badge in the results links there. For publishing and API questions, see Developers or the AI Discovery Standard.

Honest status: the fixed present.ai envelope, the origin rung, signature facts, age, history depth (an origin's count of indexed objects), locator, and advertised actions are live for indexed objects today. Per-type volatility declarations — which fields are live hints rather than stored truth — are the next increment, declared here and being built. Where this page describes more than the code yet does, the code is what changes, not the claim.
