Badges & Trust Facts

Scan reports facts, not verdicts. Every search result carries the verifiable facts behind its origin — who signed it, what binds that signature to a domain and a chain, and how long we've observed it. The badges on this site are a shorthand this page renders from those facts, for human convenience. AI agents don't get the badge; they get the raw facts and apply their own policy.

Trust badges

Each indexed origin collects independent, checkable signals. This surface sums them into a score and shows a threshold label. The score is a convenience of this GUI — it is deliberately absent from the agent-facing data.

Verified Strong standing (score ≥ 75): a signed manifest whose signing identity has an on-chain contract, with the domain and contract referencing each other.
Trusted Solid standing (score ≥ 50): signed and integrity-checked, with at least one independent binding such as DNS verification or an on-chain contract.
Claimed Self-asserted (score ≥ 25): the domain publishes a signed declaration, but nothing beyond its own word binds the signature yet.
Discovered Indexed with minimal signals (score ≥ 1): typically a structured manifest with no signature.
Open No proven signals. Not a judgment — simply nothing verified yet. Anyone can publish and sign a manifest to change this.
Signed Shown for results indexed before signal scoring: a signature is present but the full signal set hasn't been collected yet.

The agent-facing equivalent is the origin rung — a continuity ladder derived strictly from proven signals: chain-bound (contract + bidirectional domain binding) → dns → claimed → open. See About for the full contract.

Signal dots

green means the signal is verifiably present, gray means it is not. Each signal is an independent observation with a timestamp:

manifest The domain publishes a structured /.well-known/ai manifest.
selfSigned The manifest carries the author's own signature — an ownership assertion.
hashValid The content hash still matches the signature — unchanged since signing.
contractExists The signing identity has a contract on chain.
domainBinding The domain and the contract reference each other — the strongest binding.
dnsVerified The DNS owner authorized AI discovery for the domain.
platform Served from a known platform (epistery-host) that manages keys per domain.

Source badges

Where a result came from — the source is never dropped.

Signed Web Scan's own index: signed manifests, on-chain contracts, and imported signed-object catalogs. The Chain variant marks a live blockchain read.
MCP A federated result from an MCP service registry — live tool services, not stored signed objects.
Skill A registered data source matched to your query by topic, returning its callable tool manifest.

Type & status badges

vehicle An object's declared category — vehicle, official, property, and so on. Categories are public JSON-LD schemas; the projection for each is published at /api/schema.
polygon The chain a wallet or contract lives on, alongside a Contract or Wallet label for live chain reads.
Live Offline Whether a federated MCP service answered its last health check.
12 tools How many callable tools a service or skill exposes.
